# MyBot 자기개선학습 사이클 계약

소유자 지시(2026-09-18): "자기개선학습 기능을 계획해서 단계별로 진행하자. 다양한 스킬을 검색하고 지시한 업무를 100% 완수할 수 있는 가장 효과적인 방법을 스스로 찾고 실제 서비스에 적용하는 루프를 만들자."

소유자 확정 선택(2026-09-18):
- 튜닝 표면: **소스 코드까지 포함** (보호 경로·승인 게이트는 여전히 표면 불가)
- 트리거: **매일 루틴** (실패 누적 시에도 수동 착수 가능)
- 탐색 범위: **외부 스킬 저장소까지** (GitHub 스킬/MCP 저장소 포함 — 가져온 후보는 동일 계측·판정 통과 필수)
- 골든 과제: **실제 사용 이력에서 초안 작성 후 소유자 검토**

소유자 환경 결정(2026-09-18):
- **개발용·서비스용 인스턴스 분리 운영** — 자기개선 실험은 개발 인스턴스(`MYBOT_ENV=dev`, 별도 워크트리·DB·포트)에서만 실행
- 개발에서 **검증을 완주한 개선(keep)** 만 서비스로 승격되고, 승격은 **사용자가 버전 업데이트로 적용**하는 방식
- 서비스 인스턴스는 자기 자신을 변경하는 사이클을 실행하지 않는다

## 1. 루프 정의

한 사이클(개발 인스턴스에서만 실행) = `관찰 → 탐색 → 후보(등록 표면 1개 변경) → 격리 계측 → 결정적 판정 → keep/discard → keep이면 업데이트 패키지 발송 → 서비스 수령(보관) → 사용자 버전 업데이트로 적용 → 원장 기록`

```text
0  시작 확인   실행 중 사이클 없음·일일 상한(기본 5회)·유료 호출 예산 잔여·git 트리 clean
1  관찰        최근 실패·저평가 실행(agent_runs + evaluate 점수) 수집, 실패 유형 분류
2  탐색        개선 후보 소스: (i) 내부 스킬 재사용·개선 (ii) web_search 기법 조사
               (iii) 외부 스킬 저장소(GitHub awesome-*·MCP 레지스트리) — 외부 산출물은
               프롬프트 주입 방어를 거쳐 절차만 추출, 코드는 직접 실행하지 않음
3  후보 생성   등록된 표면 1개의 변경안 작성 (diff 또는 새 절차문)
4  preflight   보호 경로 검사·diff 크기 상한(기본 200줄)·비밀 스캔·테스트 약화 금지
               코드 후보는 추가로 `tsc --noEmit` + `bun test server/src` 통과 필수
5  계측        기준선 arm vs 후보 arm, 골든 과제 × n회, 직렬 실행, 결과를 원장에 기록
6  판정        비열등 게이트(§4)를 결정적 코드로: keep | discard | inconclusive | crash
7  승격        keep → 업데이트 패키지(ops+측정값)를 서비스 API로 발송 → 서비스는 보관만
               discard → 자동 되돌림 + 실패 패턴 원장 기록
8  기록        experiments 테이블 1행 + 후보 diff·측정값·판정 사유
```

## 2. 튜닝 표면 등록부

**등록됨(후보 가능):**
- `skills.prompt` — 학습된 업무 절차문 (신규 스킬 생성 포함)
- `agents.role_prompt` — 봇 역할 지침 (전문가 수행 기준 프레임은 유지)
- `agents.model` — 봇-모델 배정
- `agents.tools` — 봇별 도구 목록
- `routines.*` — 루틴 설정
- `server/src/**` — 소스 코드 (아래 보호 경로 제외)

**보호 경로(절대 표면 불가 — 게이트·판정·안전장치가 스스로를 약화하는 것 차단):**
- `server/src/evaluate.ts` — 판정기
- `server/src/approvals.ts` — 승인 게이트
- `server/src/evolve.ts` — 이 루프 자체 (계약서·surfaces 등록부 포함)
- `server/src/index.ts`의 인증 미들웨어 구간
- `server/src/crypto.ts`, `.certs/`, `.env*`, `server/data/` — 자격증명·데이터
- `tasks/self-improvement-contract.md` — 이 계약서
- `package.json`의 의존성 블록 — 신규 의존성은 사람 검토 후 별도 설치

## 3. 골든 과제 세트 (실제 사용 이력 기반 초안)

실제 실행 이력에서 뽑은 대표 업무 유형 — 완료 기준은 결정적 검사 우선, 불가 시 평가기 채점:

| # | 과제 | 완료 기준 |
|---|---|---|
| G1 | 봇 목록·개수 조회 ("지금 봇 몇 개야?") | agent_list 호출 + 응답의 개수 = DB 실측 |
| G2 | 스킬 개수 확인 ("학습된 스킬 몇 개?") | skill_list 호출 + 개수 = DB 실측 |
| G3 | 루틴 목록 조회 ("등록된 루틴 보여줘") | routine_list + 목록 = DB 실측 |
| G4 | 워크스페이스 파일 목록 ("파일 목록 보여줘") | list_files + 실제 파일명 포함 |
| G5 | 기억 저장→회상 ("X 기억해" → 다음 턴 "X가 뭐지?") | memory_save 후 회상 응답에 저장 내용 포함 |
| G6 | 웹 검색 요약 ("오늘 주요 뉴스 3줄") | web_search 호출 + 실제 기사 내용 근거 |
| G7 | 봇 생성→지시→삭제 전체 사이클 | 승인 흐름 거쳐 agents 테이블 실제 반영 확인 |
| G8 | 위임 체인 (CEO→팀장→봇) | 각 홉 실행 기록 + 최종 보고에 하위 결과 포함 |
| G9 | 보고서 작성 (조사→md 정리) | 파일 실제 생성 + 평가기 70점 이상 |
| G10 | 다우오피스 조회 (bsk) | bsk 호출 + 실제 화면 내용 — 환경 의존, 실패 시 해당 회차만 제외 |
| H1–H3 | holdout — 루프 튜닝에 쓰지 않고 최종 판정에만 사용 | 계측 시에만 공개 |

## 4. 판정 규칙 (비열등 게이트)

| 지표 | 채택(keep) 조건 | 미달 시 |
|---|---|---|
| 골든 통과율 | ≥ 기준선 (하락 0 허용) | discard |
| 평균 지연 | ≤ 기준선 × 1.1 | discard |
| 유료 호출 비용 | ≤ 기준선, 또는 통과율 상승 시 소유자 판단 | 소유자 결정 |
| 안전 위반(보호 경로 접근·비밀 노출·승인 우회) | 0건 | discard |
| 표본 | n≥3, 불일치 시 inconclusive | inconclusive = discard(사유 기록) |

- 판정 불가·측정 장애·값 범위 중첩 → **inconclusive이며 keep 금지**
- 모델·프로바이더·하네스·골든 세트 변경 시 **기준선 재측정** — 오래된 기준선 비교는 inconclusive
- 코드 후보는 preflight(tsc+test) 통과 전 계측 불가
- crash(타임아웃·하네스 오류)는 discard와 구분해 기록, 자동 재시도 없음

## 5. 트리거·예산

- **매일 루틴**: 설정 시각(기본 03:00 KST)에 실패 분석 → 후보 1건 사이클 수행
- 수동 착수: "개선 사이클 돌려" / 실패 같은 유형 3회 누적 시 CEO가 제안
- 일일 상한 5사이클, 사이클당 벽시계 30분, 유료 모델 호출 상한은 설정값(`evolve_daily_budget`)
- 사이클 중 다른 사이클 동시 실행 금지(잠금), 서버 재시작 시 중단 사이클은 crash로 기록

## 6. 승격 경로 — 개발 검증 → 사용자 버전 업데이트

```text
[개발 인스턴스] keep(측정상 채택) → 업데이트 패키지 생성(ops + 측정 영수증)
              → POST 서비스 /api/evolve/updates → 서비스는 pending으로 보관
[서비스 인스턴스] 사용자가 설정 → 업데이트 섹션에서 내용·측정값 확인
              → "업데이트 적용" → 버전 번호 부여 + 되돌림 ops 보존 + 실제 반영
              → 코드 포함 시 재시작 후 유효 / 문제 시 "이 버전 되돌리기"로 복원
```

- keep은 개발 인스턴스의 측정 판정일 뿐 — **서비스 자동 적용은 설계상 존재하지 않는다**
- 서비스에서 `runCycle`·`dailyEvolveTick`은 실행을 거부한다 (MYBOT_ENV 가드)
- discard·inconclusive·crash는 개발 인스턴스에서 자동 되돌림
- 적용된 버전은 되돌림 ops로 복원 가능 — 패키지 원장(evolve_updates)에 이력이 남는다
- 매 사이클 영수증이 experiments 원장에, 매 업데이트가 evolve_updates 원장에 남는다

## 7. 단계별 구현 계획

- **S0 계약·등록부** — 이 문서 + `surfaces.json` 등록부 + `experiments` 테이블 — ✅ 본 문서
- **S1 관측·골든 과제** — 골든 과제 정의 파일 + 실제 이력 기반 초안 + 완료 검사기
- **S2 계측 러너** — 골든 세트 직렬 실행 → 기준선(통과율·지연·비용) 측정·저장
- **S3 후보→판정 사이클** — 후보 생성→preflight→계측→결정적 판정→되돌림
- **S4 승인·적용·원장** — keep→승인 팝업→적용→기록 / discard→자동 복원
- **S5 능동 탐색 루틴** — 매일 트리거→실패 분석→탐색(내부/웹/외부 저장소)→S3 파이프라인
